- 2026-10-15T18:11Z The runner kills only the docker client; the container exits after 65 s without an answer (cli.ex grace, chosen to outlast the runner's default 60 s request timeout so no answer is cut short). With --timeout far below that, repeated hangs leave several containers alive at once, each capped at 2 GiB and 256 tasks but with no CPU cap. Declined on #54: a shorter grace reopens the lost-answer defect, and a watchdog would have to escape the runner's process group. Options: add --cpus 1 to the launcher, pass the runner's timeout into the container, or have the launcher name its container and remove it on the next start.
